## The three differences

### 1. Kavita Arora, draft B — a real gap in `verify.py`

Expected `NAME_MISMATCH`, got `CASE_FOUND` (severity drops from *problem* to *check*).

The planted error grafts an invented case name onto Shreya Singhal's real citation.
On the live corpus the name is not invented: `Dr Kavita Arora & Anr vs Union Of India & Anr`
(tid 45851935, the same-sex marriage petition) scores 100 on the name and lists no
equivalent citations. So `Checker._found_case` runs, cannot confirm `(2015) 5 SCC 1`,
and settles on "case found, citation not confirmed".

The proof it needs is already in hand: the search for `(2015) 5 SCC 1` returns
`Shreya Singhal vs U.O.I` (tid 110813550) as the top hit, and that judgment lists
`(2015) 5 SCC 1` as its own citation. `_case_not_found` would have said
"this citation belongs to Shreya Singhal, not Kavita Arora" — but it is never reached,
because a name candidate existed.

This is the headline case for a citation checker (a fabricated case name on a real
citation) and it should be reported as a problem. Saying so is not guessing under rule 2:
Indian Kanoon affirmatively lists that citation as another case's own.

**Fix:** in `_found_case`, when no candidate is tied to the cited citation, check whether
the citation belongs to a different named case before falling back to `CASE_FOUND`.

### 2. Lalita Kumari, draft A — the answer key was wrong, not the engine

Expected `WRONG_CITATION`, got `NEEDS_REVIEW`.

Two documents score 100 on the name — the 12 November 2013 Constitution Bench judgment
and a 27 February 2012 order in the same matter — and **neither lists any SCC citation**
(only AIR, AIR SCW and CRILR). The draft's planted error is a wrong SCC year.

Rule 2 forbids calling this "wrong citation": Indian Kanoon does not list the cited
reporter at all, so the volume and page cannot be contradicted. `NEEDS_REVIEW` is the
honest answer. The demo corpus carries SCC equivalents, which is why it said
`WRONG_CITATION` offline.

**Fix:** none in code. The live expectation should be `NEEDS_REVIEW`.

### 3. Maneka Gandhi, draft A — live answer is better than the key

Expected `CASE_FOUND`, got `VERIFIED`. This item has `"error": null`; the key's own note
says the expectation existed only because Indian Kanoon listed no SCC citation for the
case. The live API does list it, so `(1978) 1 SCC 248` verifies outright.

**Fix:** none in code. The live expectation should be `VERIFIED`.

## Conclusion

One real code fix (Kavita Arora). The other two are demo-corpus artefacts: the answer key
encodes what the 6-document offline corpus could support, which is not always what the
real corpus supports. The key needs per-backend expectations before `--live` can be
expected to score 25/25.
